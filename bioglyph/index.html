Structural language · Graph reasoning · Interpretable roles

A network, stated in words.

Language-encoded network topology enables large language models to reason about complex networks

Language models read text fluently and still struggle with structure, even when the whole network is handed to them as text. BioGlyph is a deterministic compiler that runs classical graph algorithms, applies one fixed rule per structural role, and writes each role as a short statement with the measurements that triggered it and what would happen if that part were removed. The model is never trained, fine-tuned, or changed.

Ucchwas Talukder Utsha, Sakib Mostafa, James Zou, Md Tauhidul Islam

The idea

Do the measurement exactly. Then say what it means.

Existing methods hand a model an edge list, the same edges as sentences, or a table of centrality measurements, and leave it to work out what any of that implies. BioGlyph does the arithmetic with classical algorithms, which are exact, and spends the language on the part language is good at: naming the role and stating its consequence.

01

Measure

Degree, betweenness, PageRank, k-core, articulation points, bridges and Leiden communities, computed on the retrieved region with a fixed seed. Same graph in, same numbers out.

02

Name

One fixed rule per role. A node above the degree threshold is a HUB; a node whose removal splits its component is a CUT_NODE. No model decides this, so the vocabulary is auditable and reproducible.

03

State the consequence

Every role carries the measurements that triggered it and what removing that part would do. The gain comes from that clause, not from the name: replacing the names with meaningless tokens costs 16.5 percent of accuracy.

The vocabulary

Eleven roles, each one a rule you can check.

The compiler is label-free: it reads connections only, never node names, gene symbols or any annotation. Every role below is decided by a threshold or an exact graph property, so the same region always compiles to the same description.

HUB

Degree above the region's threshold. Removing it drops many connections but does not split anything unless it is also a cut node.

CUT_NODE

An articulation point. The only kind of node whose removal splits its own component, and the description says into how many pieces.

BRIDGE_EDGE

An edge whose removal disconnects the two sides. The edge-level counterpart of a cut node.

COMMUNITY_CORE

Central inside its own community by intra-community degree. A module hub, not necessarily a cut point.

CROSS_COMMUNITY_CONNECTOR

Lies on many shortest paths between communities. Removing it lengthens cross-community routes rather than severing them.

BOUNDARY_NODE

A gateway spanning several communities' boundaries, by participation coefficient.

PERIPHERAL

Low k-core embeddedness and low degree. Little influence on global structure.

FRAGILE_REGION

A part of the network where a single removal disconnects a disproportionate share of what remains.

Evidence, always attached

Every role prints the measurements that triggered it, so a reader can disagree with the compiler on its own terms.

Handing a model graph neural network embeddings is no better than handing it no graph at all. Printing every measurement is worse than no graph, because the table crowds out the question. And keeping BioGlyph's structure while replacing its role names with meaningless tokens loses 16.5 percent, so the gain lives in the words, not in the layout.

The gain is not just a shorter prompt.

A named description is more compact, so a fair reader asks whether BioGlyph simply wins by fitting. In the perturbation screen on the Reactome network, neither rendering overflows on any module, every format reaches the model, and the description still leads.

It reaches a trained model without training.

A graph neural network trained directly on these questions scores 74.8%. A frozen model reading BioGlyph scores 74.1% on the same 381 questions, having never seen a training example, and it explains each answer in words a reader can check.

Abstract

Structure, said out loud.

Networks describe many systems in biology and beyond, from proteins that interact inside a cell to power grids and citation records. Understanding a network requires reasoning about its structure: which parts are most central, which connections link otherwise separate regions, how the network divides into communities, and how the network changes when a part is removed. Large language models read and reason over text fluently, yet they often struggle with this kind of structural reasoning, even when the full network is provided in text form.

Here we present BioGlyph, a compiler that states a network's structure in words. BioGlyph runs classical graph algorithms and applies one fixed rule per role. Each role is written as a short statement, such as a hub with many connections, a cut node whose removal splits the region, or a connector between communities. BioGlyph also reports the measurements that triggered the role and explains what would happen if that part were removed. The compiler uses only network connections, and the language model remains unchanged.

Across networks from several domains, small open models reading these named roles answer questions about connectivity, importance and change far more reliably than from any other rendering of the same region. They come close to a graph neural network trained on the questions themselves, with no task-specific training. The gain comes from saying what a role means for the network, not from naming it. In the budding-yeast protein interaction network, cross-community connectors are enriched for essential genes while peripheral proteins are less often essential, identified from network structure alone without seeing gene-essentiality labels. The same readable description can therefore support both model reasoning and scientific interpretation.

Read it honestly

A reasoning aid, not a replacement for the algorithm.

BioGlyph does not compete with exact graph algorithms, and should never be used where one will do. It earns its place when several structural facts must be weighed together, when the questions keep coming, and when the person asking wants an explanation or wants to disagree.

Structural enrichment is not a causal claim. That cross-community connectors are more often essential describes an association in one network against one label set; it does not establish that the position causes the essentiality.

The live workspace runs a 4-bit quantized model with a smaller context window than the study, so that it can share one GPU with the lab's other demos. Single answers there can differ from a published run, and the measurement table runs out of window sooner than it does in the paper. Read the workspace as the mechanism, not as the measurement.
